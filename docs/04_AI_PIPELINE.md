# GeoReport3D — AI Pipeline Specification

## Model strategy

Primary benchmark model:

`unsloth/Qwen3.6-27B-NVFP4`

Serving target:

`vLLM` on one Modal `L4` GPU.

The Unsloth model card currently documents the NVFP4 checkpoint as working on a 24 GB GPU and provides vLLM commands; the repository reports a 23.4 GB artifact size. Treat those facts as deployment guidance, not as proof that our complete workload will fit without tuning.

## AI router

The backend should decide whether a task needs:

- no AI
- small/cheap model
- Qwen3.6-27B

Example:

```text
Text-only page
  → CPU extraction

Clear structured table
  → CPU/table parser

Borehole image
  → Qwen vision

Complex multi-page section
  → Qwen vision + nearby text

Contradictory evidence
  → Qwen reasoning + explicit conflict report
```

## Prompt requirements

Every extraction prompt must require:

1. JSON-only output.
2. No invented values.
3. `null` for missing/unreadable values.
4. Evidence citation per extracted object.
5. Confidence in `[0,1]`.
6. Separation of observation from inference.
7. Explicit units.
8. Explicit CRS if known.

## Do not ask the model to do these things

- invent coordinates
- interpolate geological surfaces
- choose an undocumented CRS
- treat an inferred contact as observed
- silently repair contradictory data
- convert image pixels into project coordinates without calibration information

## Extraction hierarchy

```text
Source page/figure
      ↓
visual/text evidence
      ↓
AI extraction
      ↓
JSON schema validation
      ↓
deterministic validation
      ↓
conflict detection
      ↓
persist observation
```

## Multi-page sections

A geological section can span pages. Build a `FigureSequence` before asking the VLM to interpret it.

Possible sequence evidence:

- overlapping crop edges
- continuous chainage/elevation scales
- matching section identifiers
- same report figure title
- repeated legend/style
- adjacent page numbers

The reconstructed sequence must retain mapping back to the original pages.

## Caching

Cache key must include at least:

- document SHA-256
- source image/figure SHA-256
- prompt version
- model ID/revision
- preprocessing version

Do not silently reuse an answer generated by a different prompt/model version unless the policy explicitly allows it.
